# אג'נט חתימות לטפסים – תיכון אופק

אג'נט שמקבל טופס חדש, מחליט בעצמו מי צריך לחתום עליו, מבקש מהם חתימה, עוקב אחרי התוצאה, ומדווח למי שצריך – או מסלים לגורם אנושי כשאי אפשר להמשיך.

## הבעיה ולמה בחרתי בה

בכל ארגון מגיעים טפסים (בקשות רכש, יציאה לטיול, החזר הוצאות) ואף אחד לא יודע בדיוק למי הם צריכים להגיע. הכללים תלויים בפרטים: בית ספר שמזמין 25 מחשבים ב-62,000 ₪ צריך חתימה של מזכיר הכספים, של המנהלת, ושל רכז מערכות המידע, ואילו החזר של 240 ₪ דורש חתימה אחת בלבד. טפסים נתקעים אצל האדם הלא נכון, ואף אחד לא עוקב אחרי מי חתם.

זו בעיה טובה לאג'נט כי אי אפשר לפתור אותה ברצף פעולות קבוע: סדר הצעדים והחותמים משתנים מטופס לטופס, ולפעמים צריך לעצור ולבקש עזרה אנושית.

**מה האג'נט עושה:** מקבל מטרה ("טופס חדש הגיע, דאג שיגיע לאנשים הנכונים ושמי שצריך יקבל הודעה כשהכול נחתם"), קורא את הטופס ואת מדיניות החתימות, מבקש חתימות, בודק סטטוס, שולח תזכורת למי שלא חתם, ומסיים: בהצלחה (כולם חתמו, ההודעות נשלחו) או בהסלמה (טופס חסר, אין חוק מתאים, או חותם שלא מגיב).

## איך זה אג'נט ולא סקריפט

| רכיב | במימוש |
|---|---|
| **מוח** | מודל שפה של OpenAI (`gpt-4o-mini`) שמחליט מה הצעד הבא |
| **כלים** | `read_form`, `get_approval_rules`, `request_signature`, `check_signature_status`, `send_notification` (ב-`tools.py`) |
| **לולאה** | המודל בוחר כלי ← הקוד מריץ ← התוצאה חוזרת למודל ← חוזרים, עד שהמודל קורא ל-`finish` (`agent.py`) |

הקוד לא כולל שום רצף קבוע של "קודם קרא, אחר כך בקש חתימות". הסדר, המשתתפים ומועד העצירה נקבעים בכל פעם מחדש לפי הטופס.

| דרישת המבדק | איפה זה בקוד |
|---|---|
| קבלת מטרה | הודעת המערכת וההודעה הראשונה ל-`messages` |
| קבלת החלטות | המודל בוחר כלי בכל צעד, ומנמק בשדה `reason` |
| שימוש בכלים | חמישה כלים |
| בחינת התוצאה | תוצאת כל כלי חוזרת למודל והוא מחליט איך להמשיך |
| תנאי סיום | הכלי `finish` (`completed` או `escalated`), מגבלת 15 צעדים, ומגבלת זמן של 180 שניות |

## שכבות בטיחות סביב המודל

- **אימות (`verify.py`)**: כשהמודל מצהיר "הושלם", הקוד בודק בעצמו, בלי מודל, שזה נכון: סוג הטופס תואם לשם הטופס, כל מי שחייב לחתום חתם, אף אחד שלא נדרש לא התבקש, והודעות החובה נשלחו. את התנאים הנוספים (סכום, לינה, סוג ציוד) הקוד מחלץ מהטופס ומעריך בעצמו. אם האימות נכשל, הסיום נדחה והמודל מתבקש לתקן.
- **הסלמה**: כשהאג'נט מסלים, מנהלת אדמיניסטרטיבית מקבלת הודעה. אם המודל שכח לשלוח, הקוד שולח במקומו. בנוסף, הקוד בודק אם התבקשו חותמים לא נכונים ורושם אזהרה בדוח.
- **דוח ביקורת (`audit.py`)**: כל ריצה נשמרת ב-`reports/audit_XXX.json`, עם כל צעד, נימוק, תוצאה, חותמים והודעות.
- **טיפול בשגיאות**: כלי שנכשל מחזיר `{"error": ...}` והמודל רואה אותו ומחליט מה לעשות. ארגומנטים פגומים, כלי לא קיים ותקלות רשת מטופלים בלי לקרוס.
- **Timeout**: 30 שניות לכל בקשה ל-OpenAI, ומגבלת זמן כוללת לטופס.
- **מצב עבודה**: קובץ נפרד לכל טופס, עם נעילה וכתיבה אטומית נגד race condition.

## מבנה הפרויקט

```
agent.py             הלולאה של האג'נט והרצה
tools.py             הכלים ומצב העבודה
verify.py            אימות דטרמיניסטי של סיום מוצלח
audit.py             דוח ביקורת
signers.json         אנשי הצוות ותפקידיהם
approval_rules.json  מדיניות החתימות
forms/               טפסי דוגמה (001-005)
reports/             דוחות ביקורת שנוצרו בהרצה
```

## התקנה והרצה

דרישות: Python 3.10 ומעלה, ומפתח API של OpenAI.

```
py -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
set OPENAI_API_KEY=sk-proj-...
```

ב-macOS וב-Linux: `source venv/bin/activate` ו-`export OPENAI_API_KEY=...`. המפתח נשמר במשתנה סביבה ולא בקוד.

הרצה:

```
python agent.py --all        כל חמשת הטפסים, עם טבלת סיכום
python agent.py 001          טופס אחד
python agent.py 002 --keep-state    בלי לאפס את המצב הקודם של הטופס
```

כדי לשמור את הפלט לקובץ: `python -X utf8 agent.py --all > demo_output.txt`

הערה: ב-Python 3.13 מאחורי סינון אינטרנט עלולה להופיע שגיאת `CERTIFICATE_VERIFY_FAILED`. במקרה כזה Python 3.12 פותרת את זה.

## פלט הדגמה

טפסי הדוגמה בודקים התנהגויות שונות. התוצאות מהרצה אחת (`python agent.py --all`), והפלט המלא ב-`demo_output.txt`:

| טופס | תוצאה | מה קרה |
|---|---|---|
| 001 – טיול שנתי, 14,500 ₪ | הושלם ואומת, 6 צעדים | 3 חתימות (סגן מנהל, רכזת בטיחות, מזכיר כספים כי הסכום מעל 5,000 ₪), ואז הודעה למנהלת האדמיניסטרטיבית |
| 002 – רכש 25 מחשבים, 62,000 ₪ | הסלמה, 9 צעדים | מזכיר הכספים לא חתם גם אחרי תזכורת (מדומה בכוונה), והאג'נט דיווח והסלים |
| 003 – החזר הוצאות, 240 ₪ | הושלם ואומת, 5 צעדים | חתימה אחת בלבד, ללא הודעה (המדיניות לא מחייבת) |
| 004 – טופס ריק | הסלמה, 4 צעדים | האג'נט זיהה שחסר מידע ולא ניחש |
| 005 – השכרת אולם לגוף חיצוני | הסלמה, 4 צעדים | אין במדיניות חוק מתאים, והאג'נט לא המציא חותם |

## מגבלות והרחבות עתידיות

- **החתימה והפנייה לאנשים מדומות.** "חתימה" היא עדכון בקובץ, ו"הודעה" נכתבת למסך וליומן. ממשק התחברות וחתימה אמיתי, ושליחת מייל אמיתית, הם ההמשך הטבעי. כדי לשמור על פשטות, ובהתאם להנחיית המבדק ש"אג'נט פשוט שעובד עדיף", הם לא נכללו.
- **חילוץ העובדות מהטפסים** (סכום, לינה, סוג ציוד, ימי היעדרות) מבוסס על מבנה הטפסים בדוגמה. בטופס במבנה אחר, התנאי יסומן כלא-ידוע והבדיקה תישאר בידי המודל.
- **המדיניות בקובץ JSON.** בארגון אמיתי היא תגיע ממערכת ניהול הארגון.
